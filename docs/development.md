# Lorebound development

Native Ollama still lacks live-server verification; the automated coverage and other limitations are described below.

The current checkout supports blank adventure creation/resume, Story proposals with explicit acceptance, editing, Retry, committed Undo, independent Forks and bounded recovery. DEV-004A adds direct browser local narration through saved llama.cpp/Custom compatible profiles. Simulation remains the initial, visibly labeled choice. Rename/delete, world tracking, cross-passage edits, backup/restore and full host lifecycle remain later.

DEV-004B adds optional provisional Story streaming. DEV-004C adds **Test connection** in Models: one synthetic “Reply with OK.” request to the entered URL/model using a 32-token limit and the configured timeout. The browser asks llama.cpp to disable thinking for this test; Custom requests and Story generation retain their defaults. Valid complete/limited replies are labelled **Connection successful**, with a reached limit disclosed. Tests and discovery are optional; neither gates saving or generation. Results are temporary, clear on edits/closing and never change settings or story. A short test does not verify full narration or streaming, and a server that ignores model IDs cannot have its routing certified by this test.

Use Go 1.27.3 (`go.mod`), Node from [.nvmrc](../.nvmrc) and npm for development. Node is not a player runtime dependency. Dependencies are locked in `go.sum` and `frontend/package-lock.json`.

From the repository root, build the current checkout and launch a review session with one command:

```sh
bash scripts/dev.sh
```

Open [http://127.0.0.1:8080](http://127.0.0.1:8080). The command installs locked frontend dependencies, checks/builds the frontend and Go host, and runs that build in the foreground. Stop with Ctrl+C. It uses **`.local/review/lorebound.db`**, an ignored review library separate from the regular app-data library. Review stories survive stopping/restarting; the launcher never clears or seeds them. Re-running the command rebuilds current source. If Node/npm are absent from PATH, it also checks the usual NVM installation for the version in `.nvmrc`; missing Go/Node/npm must be installed first.

For a different port, run `bash scripts/dev.sh -port 8081`. Host arguments pass through, including an explicit `-data-dir /chosen/directory` override. The browser is opened manually; automatic browser launch and hot reload are not part of this command. Git Bash or another Bash environment is needed to use these development scripts on Windows.

For everyday use of an **already built binary** with the regular library, use `bash scripts/run.sh` from the repository root. That lower-level command does not rebuild. The host binds only to `127.0.0.1` and defaults to `Lorebound/lorebound.db` under Windows AppData, macOS Application Support, or Linux `${XDG_DATA_HOME:-~/.local/share}`. Changing `-data-dir` selects an existing-or-empty library; it never copies or migrates the previous one. No Gate 0 test database is imported.

The current host is launched/stopped from the terminal. Automatic browser launching, second-launch handoff, port fallback and Settings → Quit are still future work. Host/Origin restrictions are browser-request precautions, not authentication of arbitrary local processes. Local narration sends prose directly from the browser to the selected server. Go stores only fixed nonsecret profile metadata; authenticated connections are not supported yet.

The [Verify workflow](../.github/workflows/verify.yml) owns repeatable verification for pull requests and main pushes. It checks Markdown file links and rejects committed verification output. Application/tooling changes also run the build, typecheck, unit, real SQLite, Firefox/Chromium/host/recovery and exact restart suite on Ubuntu 24.04. Documentation-only changes run repository checks; manual workflow dispatch runs the full suite.

Run `agentctl verify` from the repository root after provisioning the browsers below. The gates run the existing checks in order; CI remains unchanged. Use focused local checks for debugging, or this recipe to reproduce the full CI suite:

```sh
bash scripts/build.sh
python3 scripts/check_repository.py
npm --prefix frontend run test:unit
CGO_ENABLED=0 go vet -tags server ./...
CGO_ENABLED=0 go test -count=1 -tags server -v ./...
(cd frontend && npx --no-install playwright install --with-deps firefox chromium)
bash scripts/verify-host.sh
```

Build the frontend before Go checks because the binary embeds `frontend/build`. On systems with the browsers' libraries already installed, `npx --no-install playwright install firefox chromium` suffices; `--with-deps` may need package-manager permission. Use `-tags server`; native WebView/desktop packaging is outside this application architecture.

The smoke script requires curl, Node, Firefox, Chromium and a free loopback port (`LOREBOUND_PORT`, default 18080). It refuses an occupied port and creates/removes its own temporary library, never the default user library. It verifies rejected cross-origin/rebound requests, real browser creation/resume, Story Stop/Discard/acceptance, exact structured histories across browser/process restart, simulated lost responses after actual SQLite creation/Story commits, identical-request recovery, two-tab stale-write rejection and a delayed-read navigation race. An intercepted incompatible-history response separately exercises the read-only UI; Go tests verify actual stored unsupported effects. It saves responsive screenshots at 390/768/1024/1440px in Dark/Bright test states. Bright styling is exercised through the root appearance attribute; a player-facing appearance selector is not implemented yet. The reference Cormorant Garamond, IBM Plex Sans and IBM Plex Mono fonts are bundled with OFL notices in `frontend/static/fonts`; no external browser font fetch or system installation is required. Browser checks verify actual local font loading and restored-draft resizing after a delayed font load. The main Story scrollbar runs at the sidebar edge through the full main height; narration controls expand upward as a fixed part of the same composer. They stay still while the story scrolls and normally gain their own scrollbar only when needed above the docked input. Long drafts grow the native Story textarea to a maximum of 240px (40% of main height on short windows, with an 80px floor), then scroll inside it; the surrounding composer/action bar/Send stay fixed. The full draft is retained without a new character limit. Narration keeps its independent conditional overflow. While input is blocked, a compact background field keeps pending controls visible; Discard/Stop restores capped native editing. Native Story caret scrolling and narration-section caret handling keep their text accessible. Very short windows reduce nonessential hints/spacing to retain control access.

Console output stays in Actions job logs. `browser-diagnostics-<attempt>` retains browser captures and failed-host diagnostics for seven days; its upload paths exclude databases. Missing browser dependencies or a failed check fail the job. A recipe is not a passing result: link the actual run and reviewed revision in the PR, with a brief result and limitations. For a specific local investigation, `LOREBOUND_ARTIFACT_DIR=/tmp/lorebound-artifacts` retains captures and failure diagnostics outside the repository; without it, the smoke script removes its temporary output and library.

The database retains the library epoch, adventure identity/title/version and an empty versioned Turn-0 baseline. Schema 2 adds ordered turns and distinct authored/generated passages with one current structured JSON body each. Paragraph/text/hard-break nodes serialize deterministically; each passage supports up to 20,000 Unicode codepoints (including line/paragraph separators), 1,000 paragraphs and 2,000 inline nodes. Input is not HTML or Markdown. Empty world-effect batches are valid; this slice accepts no nonempty effects. Unknown stored effects preserve readable prose but block further writes.

The current checkout uses wire version 4 and database format 11. The baseline remains version 1. Wire v4 rejects old tabs. Transactional metadata-only database upgrades fence older binaries: v3→v4 separates concurrency versions from turn counts; v4→v5 permits authored-only surviving turns after passage truncation. The additive v5→v6 upgrade creates separate noncanonical model-profile/settings tables; v6→v7 adds per-adventure narration settings. Format 9 adds author notes to format-7 libraries and preserves saved notes from format 8 while removing their revision column. Format 10 adds the per-adventure Lorebook table. Format 11 adds optional Story context settings to saved model profiles. Older binaries reject the newer format. Existing baselines, prose, drafts, epoch and receipt rows remain unchanged; old wire-v2/v3 operations are rejected rather than silently upgraded. Opening a DEV-002A schema-1 library atomically adds the nonspatial Story tables, preserving existing adventures, baselines, epoch and original creation receipts. Unsupported libraries fail without replacement. **B9-D12 spatial migration remains deferred.** No old passage revisions or replay checkpoints are stored.

TypeScript prepares the complete turn and reconstructs current history. `LibraryService.Commit` technically validates IDs/order/documents, expected version and epoch before one SQLite transaction saves the turn, passages, version and receipt. Story operation IDs are scoped to an adventure. Identical retry returns the original result even after later commits; changed payload reuse rejects. The browser then refetches current canon. A save with an uncertain outcome blocks new submissions until recovery; a stale submission refetches and retains live authored input for a fresh decision.

DEV-003C adds a separate shared latest Story composer draft in the current checkout. Input autosaves after 600 ms of inactivity; saved input restores on reopen without accepting a turn. Clearing input saves an empty value. Status distinguishes a saved draft from accepted story and offers Retry draft after failure. Generated candidates remain ephemeral, and final unsaved keystrokes can be lost. Acceptance consumes matching saved input atomically; different latest input survives. This uses an additive nonspatial database v2→v3 upgrade, preserving history/identity/receipts; older binaries reject the newer format.

Merged DEV-002C PR #8 extends the verification harness with consecutive cross-tab commits during a delayed read, retained input, deferred refresh after Discard, failed post-commit reads, recovery after newer accepted history, failed conflict reload and last-tab closure. Its coordinator queues background hints until safe idle; blocked errors require deliberate Reload. Generate is disabled during authoritative refresh while input remains editable. See [PR #8](https://github.com/Levelleor/lorebound/pull/8) for merged verification evidence.

DEV-003E replaces the custom input Undo/Redo from PR #14 with **Undo turn N** below the latest accepted turn. Click it, review the named boundary in the composer overlay, then Confirm Undo or Cancel/Escape. Confirmation permanently removes all saved passages of that turn, reconstructs the surviving supported history and preserves unfinished input. Repeated Undo reaches the initial baseline; generate/accept can then continue with a different next turn in the same adventure. There is no canonical Redo/archive; Fork first to keep the original future. Ordinary textarea editing and latest draft autosave remain.

Adventure versions are monotonic concurrency tokens, independent of current turn count; Undo increments the version while removing a turn. Append and Undo use the same atomic Go/SQLite Commit/receipt path, guarded by expected version and library epoch. Recover Undo retries the identical operation after an uncertain result, including if another context has already continued. Original append/Fork receipt recovery reads current canon after later Undo without restoring removed content. Nonempty world effects and independent correction/module replay remain unsupported; this covers the complete existing Story-only zero-effects state.

DEV-003F adds inline editing for **accepted generated continuations** in the current checkout. Click Edit below a continuation, type in place, then use Review edit in the shared composer overlay. Keep Later Turns replaces only that passage; Delete All After Point also removes every later turn. Continue Editing/Escape returns to the draft; Discard leaves accepted story unchanged. DEV-003G extends this flow to authored passages below; cross-passage changes remain later. Nonempty document limits still apply.

Passage drafts use separate `passage:<id>` latest-value slots in the existing draft table, restoring when that passage's editor reopens. Empty drafts remain distinct from absent drafts. Confirmation consumes only matching text; discard does not flush discarded unsent edits over another tab's saved draft. Stale canonical writes require deliberate review of current accepted prose; lost responses use Recover edit with the original request. Truncation/Undo remove drafts whose passage targets were deleted. Composer input and independent Forks remain separate. No schema migration or old-body archive is introduced.

DEV-003G extends the same editor and per-target drafts to **accepted player-authored Story text**. Keep Later Turns retains the generated continuation in the same turn and all later turns. Delete All After Point removes that continuation and every later turn, retaining the edited authored passage and its turn identity. This authored-only turn remains editable, forkable and undoable; a newly generated/accepted pair continues as the next turn. The confirmation states this passage boundary explicitly. Database v5 changes only the compatibility marker; no passage table rewrite or spatial migration is involved.

DEV-003H adds **Undo edit / Redo edit** only inside an open accepted-passage editor. Use the buttons or Ctrl/⌘+Z, Ctrl/⌘+Shift+Z, or Ctrl+Y while the passage has focus. Undo restores its text selection; a new edit clears temporary redo. Continue Editing preserves the session. Closing/reloading, restoring a different shared draft or confirming an edit clears it. Only the latest draft text autosaves; older temporary values are never stored. This does not restore overwritten accepted prose or removed turns.

DEV-003I retains a confirmed Story save's immutable request in browser session storage before dispatch. After a same-tab reload, **Recover save** checks the original operation before allowing new actions; it never regenerates, rebases, repeats an old deletion or restores a later-undone turn. Retained request text is available for copying. Storage access/format/cleanup problems block safely with recovery feedback. Canon and shared latest drafts still live in Go-owned SQLite; unconfirmed candidates and temporary editor history are not journaled. This covers turn acceptance, committed Undo and authored/generated passage edits, within the same browser tab and origin/port. Closing the tab, clearing session data, browser crashes and creation recovery have no new guarantee. Fork reload recovery is covered separately below.


DEV-003J retains an uncertain Fork's immutable request and chosen turn number in source-tab session storage before sending it. Reload the same tab and use **Recover fork** to resolve the original operation; the source may have changed in another tab, and the destination opens with its current accepted history. If the source turn disappeared, recovery remains above the reader. After reload, **Open fork** opens the resolved destination in a new tab; it does not create another adventure. Unavailable/malformed storage or failed cleanup blocks new submissions with **Retry fork recovery access**. Source input stays in its SQLite draft and is never copied. The same-tab/origin/port and tab-close/crash limits above apply.

## Provisional local streaming (DEV-004B)

With a saved llama.cpp/Custom local connection selected, check **Stream output** above the Story input before generating. This unchecked-by-default preference lasts only for the current workspace session; it does not change saved profiles. The server must support compatible `text/event-stream` chat-completion deltas. Uncheck it to deliberately request the existing completed JSON response mode; failures never switch modes or providers automatically.

Incremental prose appears in the blue provisional region. Accept is available only after normal completion and the terminal stream marker, and still requires your explicit click. Stop, failure, Retry, navigation, reload and closing the tab discard uncommitted AI output; saved player input follows its separate draft policy. Browser abort cannot guarantee remote model computation has stopped. Hosted CI uses simulated provider output with real Firefox/Go/SQLite streaming and persistence checks; live-model/browser/server compatibility is a separate, limited result when exercised.

## Local generation details (DEV-004D)

After starting a local Story generation, expand **Generation details** below the proposed output. It shows the captured requested connection/model, response mode, timeout and Story narration stage. Completion, failure or Stop adds observed browser elapsed milliseconds; this includes network/validation time and does not measure server computation. Server-effective defaults and model routing remain unknown.

Servers are not probed or asked for extra stream options to obtain usage. Retry replaces the latest report; reloading or leaving the workspace clears it. Simulation has no provider report. The disclosure saves no diagnostic history and does not change explicit Story acceptance.

## Native Ollama connections

Partial/limited/failed output and tool calls are discarded; model thinking is not shown as prose. Stop aborts the browser request, without guaranteeing the remote server has stopped computation. Native diagnostics expose reported input/output token counts; total stays **Not reported**. No generation sampling or thinking override is added.

The existing optional synthetic Test connection uses the same 32-token cap as other profiles, mapped to `options.num_predict`. CI exercises simulated Ollama responses through real Linux Firefox and Go/SQLite; installed/live Ollama and arbitrary models/OS combinations are not certified.

## Current adventure narration style

DEV-004G adds a **Narration style** stack-icon button beside the primary composer controls. It opens a compact inline shelf above the story input on desktop and mobile. Set optional perspective, tense, genre, tone, pacing, prose length and custom style instructions, then **Save narration settings**. Cancel/Escape or toggling the button closed leaves saved values unchanged. Saving closes the shelf and returns focus to the button when the other section has no unsaved edits. Cancel closes the shelf. The input stays editable, while generation and other story actions wait until the shelf is saved or closed. Settings persist per adventure; **Reload settings** refreshes the style fields and retains any unsaved author notes. Retrying an identical uncertain save does not add another revision.

The same shelf contains an **Author notes** disclosure with one optional freeform value per adventure, up to 4,000 Unicode code points. **Save author notes** replaces the current saved text. If two tabs save notes, the last successful save determines the current value. The shelf keeps unsaved style edits available when saving notes, and it keeps unsaved notes available when saving style. A failed or unconfirmed notes save leaves the edited text in the shelf for retry. Author notes are saved independently of the story, world state, composer input and drafts.

Each local Story Generate/Retry reads the then-current saved style and author notes before building the request, including changes from other tabs. The narrator system message includes current narration style guidance, nonblank author notes and selected Lorebook text, in that order. The accepted history and player input follow in separate messages. Empty notes add no text at all. Notes never alter accepted history, provider decoding parameters or the retry/pipeline selection. **Generation details → Narration style guidance** shows the captured attempt's style text, and **Generation details → Author notes** shows the exact notes text captured for that attempt or an explicit "No author notes were sent with this attempt." state. Changing settings affects future requests only; existing accepted prose/world state, the adventure's canonical version and composer input are unchanged. No character selection or style-preset library is required. Simulation ignores these preferences, and connection discovery/tests receive no story or style text.

Style and author-note adherence and response length are best-effort writing preferences, not provider sampling values or token caps. An optional per-profile character limit can block an attempt with oversized notes. Model context capacity remains unknown. Genre/tone allow up to 200 code points each, custom instructions 2,000 and author notes 4,000 (browser form limits can be stricter for supplementary Unicode on the style fields). Invalid, invalid-Unicode or unreadable settings/notes block generation visibly rather than silently omitting guidance. Stop during either read prevents a late model request.

Database format 9 stores the current author notes in a separate, noncanonical `author_notes` table. Reads and saves are scoped to the adventure and library epoch. Opening format 7 adds the table, while opening format 8 preserves the saved notes and drops the revision column. Both upgrades are transactional and preserve canon, drafts, profiles, style settings and epoch. Fork copies the saved style and notes at the time of the Fork, even when the player selects an earlier turn. This is the first bounded slice of accepted IDEA-0025/PRD-0026: only one current-adventure author-notes layer and its transmitted-text inspection. Global and scene-scoped notes, template-derived starting directions, different per-task-role instruction sections, note-conflict arbitration and the token-budgeted context builder/inspector (IDEA-0024) remain undelivered; no document or UI claim here certifies those broader accepted requirements.

## Manual Lorebook

Open **Lorebook** immediately to the left of the Story input. Choose **New entry**, enter a title, type and optional description, then **Save entry**. Titles allow up to 160 Unicode code points and descriptions allow up to 4,000. Saved entries begin excluded. To send one to the narrator, check **Include in Story generation** and save again. Closing the drawer keeps unsaved edits available in the current workspace. **Reload entries** reads saved values and keeps unsaved edits available for review. Each adventure owns its entries and selection. Fork copies them at the time of the Fork so subsequent changes are independent.

Local **Generate** and **Retry** read saved lore immediately before dispatch, including saves from other tabs. The request contains selected entries in creation order with their type, title and description. A configured Lorebook character limit can omit whole entries that do not fit. **Generation details** shows the requested entries and the exact lore text sent for that attempt. Current provider profiles lack a reliable context limit and tokenizer for sizing the whole request. The inspector labels capacity as unknown, and a recognized provider overflow error keeps the player's input available. Simulation continues with its standalone fixture response. This is the manual entry and selection slice of [PRD-0021](product/PRD-0021-entity-based-lorebook.md). Entity links, live world-state integration, automatic activation and measured context budgeting remain follow-up scope.

## Story context presets

In **Model settings**, open a saved connection and choose **Low**, **Medium** or **High** under **Story context**. The four fields show the limits for author notes, accepted history, Lorebook and player input. Editing any value switches the profile to **Custom** and saves the change immediately. Choosing a built-in preset replaces the four current values. **Limits off** restores unbounded sections. A new connection saves its chosen limits with the connection.

Generate and Retry count Unicode code points in the rendered sections, including headings and separators. The oldest history is trimmed first. Manually included Lorebook entries are considered in order, and a large entry can be skipped to fit a later one. Oversized author notes or player input block dispatch and remain available to edit. The inspector shows the attempt’s character counts and limits, whether history was trimmed, which Lorebook entries were skipped and the exact lore text sent. Counts apply to prompt text. The model’s token capacity remains unknown.

## Saved model resolution

Generate and Retry resolve the active library's current saved connection settings and model before sending a request. Saved changes from another tab affect the next attempt, not an in-flight one; unsaved settings do not. If settings cannot be read, the app keeps the input and reports the failure instead of falling back to Simulation.

## Agentctl workflow prerequisites

`agentctl init` provides the canonical repository protocol. The saved Ultracode workflow and roles come from `Levelleor/dev-workflow` revision `a16c6ab7d4f4e7864029da3b98dbfe94d5635183`. The workflow uses the host-capable Pi Ultracode fork and the `pi-ultracode-agentctl-bridge` extension. Install/authorize those in Pi's user configuration and trust the repository only after reviewing the workflow. The repository does not grant capabilities itself.

The upstream sequential workflow implements a story and attempts to commit, push and open a PR after independent review; invoking it requires explicit authorization for those actions. It does not merge. Use the CLI directly when authorization is limited to local work. No workflow task was launched during migration.
