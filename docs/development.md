# Lorebound development

The current checkout supports blank adventure creation/resume, Story proposals with explicit acceptance, editing, Retry, committed Undo, independent Forks and bounded recovery. DEV-004A adds direct browser local narration through saved llama.cpp/Custom compatible profiles. Simulation remains the initial, visibly labeled choice. [NOW](../planning/development/NOW.md) distinguishes reviewed branch work from verified main; [DEV-004A scope](../planning/development/requirements/DEV-004A.md) owns coverage and limits. Rename/delete, world tracking, cross-passage edits, backup/restore and full host lifecycle remain later.

Use Go 1.27.3 (`go.mod`), Node from [.nvmrc](../.nvmrc) and npm for development. Node is not a player runtime dependency. Dependencies are locked in `go.sum` and `frontend/package-lock.json`.

From the repository root, build the current checkout and launch a review session with one command:

```sh
bash scripts/dev.sh
```

Open [http://127.0.0.1:8080](http://127.0.0.1:8080). The command installs locked frontend dependencies, checks/builds the frontend and Go host, and runs that build in the foreground. Stop with Ctrl+C. It uses **`.local/review/lorebound.db`**, an ignored review library separate from the regular app-data library. Review stories survive stopping/restarting; the launcher never clears or seeds them. Re-running the command rebuilds current source. If Node/npm are absent from PATH, it also checks the usual NVM installation for the version in `.nvmrc`; missing Go/Node/npm must be installed first.

For a different port, run `bash scripts/dev.sh -port 8081`. Host arguments pass through, including an explicit `-data-dir /chosen/directory` override. The browser is opened manually; automatic browser launch and hot reload are not part of this command. Git Bash or another Bash environment is needed to use these development scripts on Windows.

For everyday use of an **already built binary** with the regular library, use `bash scripts/run.sh` from the repository root. That lower-level command does not rebuild. The host binds only to `127.0.0.1` and defaults to `Lorebound/lorebound.db` under Windows AppData, macOS Application Support, or Linux `${XDG_DATA_HOME:-~/.local/share}`. Changing `-data-dir` selects an existing-or-empty library; it never copies or migrates the previous one. No Gate 0 test database is imported.

Before merge approval, the agent provides a checked running URL or this single launch command and a short walkthrough tailored to the change. The walkthrough states actions, expected results and limitations; user feedback precedes finalise/merge approval. CI handles automated checks separately.

The current host is launched/stopped from the terminal. Automatic browser launching, second-launch handoff, port fallback and Settings → Quit are still future work. Host/Origin restrictions are browser-request precautions, not authentication of arbitrary local processes. Local narration sends prose directly from the browser to the selected server. Go stores only fixed nonsecret profile metadata; authenticated connections are not supported yet.

The [Verify workflow](../.github/workflows/verify.yml) owns repeatable verification for pull requests and main pushes. It checks Markdown file links and rejects generated planning output. Application/tooling changes also run the build, typecheck, unit, real SQLite, Firefox/host/recovery and exact restart suite on Ubuntu 24.04. Documentation-only changes run repository checks; manual workflow dispatch runs the full suite.

Use focused local checks for development/debugging, or this recipe when reproducing the full CI suite. Routine implementation/review/closure does not require every agent to repeat it locally:

```sh
bash scripts/build.sh
python3 scripts/check_repository.py
npm --prefix frontend run test:unit
CGO_ENABLED=0 go vet -tags server ./...
CGO_ENABLED=0 go test -count=1 -tags server -v ./...
(cd frontend && npx --no-install playwright install --with-deps firefox)
bash scripts/verify-host.sh
```

Build the frontend before Go checks because the binary embeds `frontend/build`. On systems with Firefox's libraries already installed, `npx --no-install playwright install firefox` suffices; `--with-deps` may need package-manager permission. Use `-tags server`; native WebView/desktop packaging is outside this application architecture.

The smoke script requires curl, Node, Firefox and a free loopback port (`LOREBOUND_PORT`, default 18080). It refuses an occupied port and creates/removes its own temporary library, never the default user library. It verifies rejected cross-origin/rebound requests, real browser creation/resume, Story Stop/Discard/acceptance, exact structured histories across browser/process restart, simulated lost responses after actual SQLite creation/Story commits, identical-request recovery, two-tab stale-write rejection and a delayed-read navigation race. An intercepted incompatible-history response separately exercises the read-only UI; Go tests verify actual stored unsupported effects. It saves responsive screenshots at 390/768/1024/1440px in Dark/Bright test states. Bright styling is exercised through the root appearance attribute; a player-facing appearance selector is not implemented yet. Font stacks use the approved serif/sans/mono fallbacks when the named fonts are not installed; no external font fetch is required.

Console output stays in Actions job logs. `browser-diagnostics-<attempt>` retains browser captures and failed-host diagnostics for seven days; its upload paths exclude databases. Missing browser dependencies or a failed check fail the job. A recipe is not a passing result: link the actual run and reviewed revision in the PR, with a brief result and limitations. Reuse that result during review instead of duplicating a local suite or copying logs into planning. For a specific local investigation, `LOREBOUND_ARTIFACT_DIR=/tmp/lorebound-artifacts` retains captures and failure diagnostics outside the repository; without it, the smoke script removes its temporary output and library.

The database retains the library epoch, adventure identity/title/version and an empty versioned Turn-0 baseline. Schema 2 adds ordered turns and distinct authored/generated passages with one current structured JSON body each. Paragraph/text/hard-break nodes serialize deterministically; each passage supports up to 20,000 Unicode codepoints (including line/paragraph separators), 1,000 paragraphs and 2,000 inline nodes. Input is not HTML or Markdown. Empty world-effect batches are valid; this slice accepts no nonempty effects. Unknown stored effects preserve readable prose but block further writes.

The current checkout uses wire version 4 and database format 6; the baseline remains version 1. Wire v4 rejects old tabs. Transactional metadata-only database upgrades fence older binaries: v3→v4 separates concurrency versions from turn counts; v4→v5 permits authored-only surviving turns after passage truncation. The additive v5→v6 upgrade creates separate noncanonical model-profile/settings tables; older binaries reject the newer format. Existing baselines, prose, drafts, epoch and receipt rows remain unchanged; old wire-v2/v3 operations are rejected rather than silently upgraded. Opening a DEV-002A schema-1 library atomically adds the nonspatial Story tables, preserving existing adventures, baselines, epoch and original creation receipts. Unsupported libraries fail without replacement. **B9-D12 spatial migration remains deferred.** No old passage revisions or replay checkpoints are stored.

TypeScript prepares the complete turn and reconstructs current history. `LibraryService.Commit` technically validates IDs/order/documents, expected version and epoch before one SQLite transaction saves the turn, passages, version and receipt. Story operation IDs are scoped to an adventure. Identical retry returns the original result even after later commits; changed payload reuse rejects. The browser then refetches current canon. A save with an uncertain outcome blocks new submissions until recovery; a stale submission refetches and retains live authored input for a fresh decision.

Generated candidates remain ephemeral, and final unsaved keystrokes can be lost. Acceptance consumes matching saved input atomically; different latest input survives. This uses an additive nonspatial database v2→v3 upgrade, preserving history/identity/receipts; older binaries reject the newer format. DEV-003E replaces the custom input Undo/Redo from PR #14 with **Undo turn N** below the latest accepted turn. Click it, review the named boundary in the composer overlay, then Confirm Undo or Cancel/Escape. Confirmation permanently removes all saved passages of that turn, reconstructs the surviving supported history and preserves unfinished input. Repeated Undo reaches the initial baseline; generate/accept can then continue with a different next turn in the same adventure. There is no canonical Redo/archive; Fork first to keep the original future. Ordinary textarea editing and latest draft autosave remain.

Adventure versions are monotonic concurrency tokens, independent of current turn count; Undo increments the version while removing a turn. Append and Undo use the same atomic Go/SQLite Commit/receipt path, guarded by expected version and library epoch. Recover Undo retries the identical operation after an uncertain result, including if another context has already continued. Original append/Fork receipt recovery reads current canon after later Undo without restoring removed content. Nonempty world effects and independent correction/module replay remain unsupported; this covers the complete existing Story-only zero-effects state. [Scope and verification status](../planning/development/requirements/DEV-003E.md), [current review handoff](../planning/development/NOW.md).

DEV-003F adds inline editing for **accepted generated continuations** in the current checkout. Click Edit below a continuation, type in place, then use Review edit in the shared composer overlay. Keep Later Turns replaces only that passage; Delete All After Point also removes every later turn. Continue Editing/Escape returns to the draft; Discard leaves accepted story unchanged. DEV-003G extends this flow to authored passages below; cross-passage changes remain later. Nonempty document limits still apply.

Passage drafts use separate `passage:<id>` latest-value slots in the existing draft table, restoring when that passage's editor reopens. Empty drafts remain distinct from absent drafts. Confirmation consumes only matching text; discard does not flush discarded unsent edits over another tab's saved draft. Stale canonical writes require deliberate review of current accepted prose; lost responses use Recover edit with the original request. Truncation/Undo remove drafts whose passage targets were deleted. Composer input and independent Forks remain separate. No schema migration or old-body archive is introduced. [Scope and verification](../planning/development/requirements/DEV-003F.md) and [NOW](../planning/development/NOW.md) own current readiness/merge status.

Delete All After Point removes that continuation and every later turn, retaining the edited authored passage and its turn identity. This authored-only turn remains editable, forkable and undoable; a newly generated/accepted pair continues as the next turn. The confirmation states this passage boundary explicitly. Database v5 changes only the compatibility marker; no passage table rewrite or spatial migration is involved. DEV-003H adds **Undo edit / Redo edit** only inside an open accepted-passage editor. Use the buttons or Ctrl/⌘+Z, Ctrl/⌘+Shift+Z, or Ctrl+Y while the passage has focus. Undo restores its text selection; a new edit clears temporary redo. Continue Editing preserves the session. Closing/reloading, restoring a different shared draft or confirming an edit clears it. Only the latest draft text autosaves; older temporary values are never stored. This does not restore overwritten accepted prose or removed turns. DEV-003I retains a confirmed Story save's immutable request in browser session storage before dispatch. After a same-tab reload, **Recover save** checks the original operation before allowing new actions; it never regenerates, rebases, repeats an old deletion or restores a later-undone turn. Retained request text is available for copying. Storage access/format/cleanup problems block safely with recovery feedback. Canon and shared latest drafts still live in Go-owned SQLite; unconfirmed candidates and temporary editor history are not journaled. This covers turn acceptance, committed Undo and authored/generated passage edits, within the same browser tab and origin/port. Closing the tab, clearing session data, browser crashes and creation recovery have no new guarantee. Fork reload recovery is covered separately below. [Requirements/coverage](../planning/development/requirements/DEV-003I.md) and [NOW](../planning/development/NOW.md) own verification and merge status.


DEV-003J retains an uncertain Fork's immutable request and chosen turn number in source-tab session storage before sending it. Reload the same tab and use **Recover fork** to resolve the original operation; the source may have changed in another tab, and the destination opens with its current accepted history. If the source turn disappeared, recovery remains above the reader. After reload, **Open fork** opens the resolved destination in a new tab; it does not create another adventure. Unavailable/malformed storage or failed cleanup blocks new submissions with **Retry fork recovery access**. Source input stays in its SQLite draft and is never copied. The same-tab/origin/port and tab-close/crash limits above apply. [Requirements/coverage](../planning/development/requirements/DEV-003J.md) and [NOW](../planning/development/NOW.md) own verification/merge readiness.


DEV-004A adds **Models** in the header. Start your llama.cpp server separately, open Models, supply its actual HTTP(S) API base URL (usually ending in `/v1`), enter a model ID and choose **Save and use profile**. **Discover models** is optional; a failed or empty list does not prevent entering an ID manually. The server must allow the Lorebound browser origin; browsers can also restrict private-network or mixed-content requests. The dialog saves multiple shared profiles, permits editing/deletion and offers **Use Simulation · No AI** explicitly. Do not put credentials in profile fields. URLs with credentials/query/fragment are rejected; cookies/referrers and redirects are disabled. No Go inference proxy is used.

In an adventure, enter Story text and Generate. A completed compatible response appears as a proposal; Retry replaces it, Discard removes it and only **Accept turn** writes canon. Stop, timeout, navigation or a failed/malformed/incomplete response cannot accept partial output. Your available input remains for retry. A selected local profile never falls back to Simulation. To review without a running model, save an unreachable local endpoint and confirm the recoverable error, then deliberately choose Simulation to explore the existing proposal/acceptance flow.

The provider subset is unauthenticated compatible text through `/chat/completions`, with optional `/models`; DEV-004B adds opt-in streaming below. Cloud credentials and advanced parameters remain later. The [planning workflow](../planning/development/README.md#local-llamacpp-testing) records the owner-authorised local llama.cpp launch recipe. DEV-004A has a limited live Qwen3/ROCm/Linux Firefox smoke result, described in its requirements and primary PR; universal model/server compatibility is not certified. CI uses a simulated compatible HTTP server with real Firefox CORS/network/abort behavior and Go/SQLite persistence, including settings conflicts and exact browser/process reopen. Provider-specific variations and OS/browser combinations outside that evidence remain unverified.

## Provisional local streaming (DEV-004B)

With a saved llama.cpp/Custom local connection selected, check **Stream output** above the Story input before generating. This unchecked-by-default preference lasts only for the current workspace session; it does not change saved profiles. The server must support compatible `text/event-stream` chat-completion deltas. Uncheck it to deliberately request the existing completed JSON response mode; failures never switch modes or providers automatically.

Incremental prose appears in the blue provisional region. Accept is available only after normal completion and the terminal stream marker, and still requires your explicit click. Stop, failure, Retry, navigation, reload and closing the tab discard uncommitted AI output; saved player input follows its separate draft policy. Browser abort cannot guarantee remote model computation has stopped. Hosted CI uses simulated provider output with real Firefox/Go/SQLite streaming and persistence checks; live-model/browser/server compatibility is a separate, limited result when exercised.
