# Lorebound Branding and Engine Split

## Idea
Consider using Lorebound for the application and a separate reusable engine brand such as Fablecore.

## Why consider it?
A modular architecture might eventually support distinct engine and product distributions.

## Rough behaviour
Reserve a consistent app name; consider splitting only if reuse or API distribution warrants it.

## Variations and alternatives
Single Lorebound project with no second brand.

## Open questions and risks
- Are trademarks/domains available and is a split worth maintenance overhead?

## Evaluation notes
- Origin: **agent**. Assistant-proposed option, not a confirmed user preference.
- This note is not an implementation specification or an accepted project decision.
